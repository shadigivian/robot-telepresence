# Feedar hostname separation and authentication boundary

`VITE_BOSS_ORIGIN` and `VITE_APP_ORIGIN` select the Boss and organization login surfaces by exact URL origin. `VITE_API_ORIGIN` reserves the shared service endpoint. The same static bundle can be deployed to both hosts with the same three values. Use HTTPS in deployment; the localhost HTTP exception exists for local checks. An unknown host shows only an unavailable login surface. Configure DNS, TLS, static hosting, and SPA hash-route fallback separately. Values are examples in `.env.example`; no Feedar domain is embedded in source.

This repository's `feedar-demo/` is a browser-only simulation. It has **no shared backend, server session, production identity provider, or cross-subdomain datastore**. In the default public build, configured Boss/App origins show separate styled email/password forms but do not grant access; signing in operationally requires a real backend provider. The public form gives a clear integration error and stores/transmits no password. Protected panels cannot be reached by changing a hash route or a browser-stored demo identity. An explicitly enabled, server-gated staging build can grant browser-local demo access but does not provide real authentication. The demo preview switcher and sample account buttons have been removed from React and do not appear in development, staging or production.

The local demo remains on `localhost` or `127.0.0.1` in development and preserves all earlier workflows. A separate, opt-in staging build can enable the same simulation on configured Boss/App origins only when the entire site is protected by a server-side gate; see [STAGING_DEMO.md](STAGING_DEMO.md). Its IndexedDB data is same-origin only. Separate Boss/App hosts cannot share its tickets, robot sessions, notifications or credits. Never use that datastore as a cross-host bridge or treat client-side role checks as production security.

Before enabling operational login, a backend must provide authenticated `/session` and `/login` endpoints, an authoritative role/organization claim, server-side action authorization, a shared tenant datastore, and an audited one-time Boss transfer handshake. The transfer should create a short-lived, single-use server record bound to the Boss identity and target organization, redeem it server-side on the App host without putting a reusable token in the URL, and invalidate it on return/logout. The current BrowserStore and DemoService are not substitutes for those endpoints. No backend was found in this static package, and no unsafe transfer was added.

Local test: `VITE_BOSS_ORIGIN=http://127.0.0.1:4183 VITE_APP_ORIGIN=http://127.0.0.1:4184 npm run build`; serve that bundle at both ports and verify each host-specific login, missing demo controls, and denial of protected routes. The default `npm run dev` remains the legacy local demo for regression tests.
